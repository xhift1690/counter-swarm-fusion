The clean separation between drones and decoys is partly real (two independent classifying sensors) and partly an artifact of a deliberately simple classification model that becomes overconfident quickly. Design choices

SAPIENT-aligned data model

Detections, fusion and tracks are kept as three separate concepts, mirroring the SAPIENT interface semantics.

Sensor capability profiles

Each synthetic sensor declares its own detection probability, false alarm rate, range and classification ability.

Track lifecycle as operator trust

Tracks move from tentative to confirmed to dropped, like a decision module managing confidence.

Scope

Fusion software only. No sensor design, jamming or interceptor logic.

Known limitations

Naive classification fusion

A multiplicative Bayesian update that drives scores toward 0 or 1 too fast. Next: calibrated likelihoods or a Beta-Binomial / Dirichlet model.

Constant-velocity motion model

Real drones maneuver. An Interacting Multiple Model filter would handle turns better.

Single-assignment data association

Gated nearest-neighbor with the Hungarian algorithm. Dense swarms would benefit from JPDA or multi-hypothesis tracking.

Track fragmentation

Some duplicate tracks form from false alarms. A duplicate-suppression heuristic helps; per-sensor tuning would be the principled fix.
